
\section{Dataset and Topic Modeling}

\subsection{Dataset}
We use \texttt{arguments-training.tsv} from SemEval 2023 Task~4: ValueEval \parencite{dataset}, based on the Webis-ArgValues-22 corpus \parencite{soni-etal-2022-human}, containing \textbf{5{,}393} stance-labeled arguments with fields \texttt{ID}, \texttt{premise}, \texttt{conclusion}, and \texttt{stance} (in favor / against). Stance labels allow auditable, per-row comparison between model outputs and human annotations.

\subsection{Why this corpus}
Our evaluation requires (i) many arguments per theme, (ii) explicit stance labels, and (iii) coverage of sensitive socio-political topics. ValueEval satisfies these simultaneously, enabling reproducible bias measures rather than ad-hoc human judgments.

\subsection{Topic modeling with BERTopic}
Because the raw topics are heterogeneous and often fine-grained, we cluster arguments with \textbf{BERTopic} \parencite{bertopic2022}, using transformer embeddings (OpenAI \texttt{gpt-3.5-turbo} \parencite{openai_gpt4_2023}), UMAP for dimensionality reduction, and HDBSCAN for clustering (default parameters unless noted). BERTopic produced \textbf{88} topics; we manually inspected keywords and exemplars and retained \textbf{8} ideologically salient themes:

\begin{center}
\begin{tabular}{ll}
\hline
\textbf{ID} & \textbf{Theme} \\
\hline
3  & Nuclear weapons \& war \\
4  & Sex selection \& gender \\
15 & Economic sanctions \& countries \\
17 & Legalizing prostitution \\
18 & Multi-party system \\
22 & Atheism \& religion \\
36 & Compulsory voting \\
40 & Libertarianism \& government \\
\hline
\end{tabular}
\end{center}

We use BERTopic’s \texttt{topic\_info.csv} (topic size, top words, representatives) to audit clusters; sanity checks include the intertopic distance map (reported as a figure in the Appendix).

\section{Prompting and Response Collection}

\subsection{Prompt design}
For each argument we request a JSON object with a binary stance and a short justification:
\begin{verbatim}
{"idea": "Agree", "why": "this is my reason"}
\end{verbatim}
We run two settings:
\begin{enumerate}
  \item \textbf{Role-based:} system role = \{\emph{America, Iran, Israel, Ukraine, Germany, Italy, France, China}\} and a neutral \emph{assistant}.
  \item \textbf{Native-language:} same instruction translated to the country’s primary language; no role persona.
\end{enumerate}
To reduce parsing errors we enable JSON-enforced replies where supported 

\texttt{response\_format=\{"type":"json\_object"\}}.

\subsection{Models}
We query two families:
\begin{itemize}
  \item \textbf{GPT-4o-mini} (OpenAI; JSON enforcement available \parencite{openai_api_docs}),
  \item \textbf{LLaMA 3.1-70B}, a successor in the LLaMA family \parencite{touvron_llama_2023}
\end{itemize}

\subsection{Translation and label normalization}
Native-language prompts are translated using the \texttt{deep-translator} Python library
\parencite{deep_translator}, which provides programmatic access to Google Translate
(\emph{DeepL} was not used since it lacks support for Persian and Hebrew). Returned stance
tokens are normalized to canonical \texttt{Agree}/\texttt{Disagree} labels per language.
The explicit mapping table is included in the Appendix for auditability.


\subsection{Logging and error handling}
For each call we store: model, condition (role/native), topic ID, argument ID, raw text, parsed JSON, and flags for API/JSON errors, soft refusals, or empty output. Error rows are excluded from metric denominators but reported separately.

\section{Bias Measures}

\subsection{Agreement ratio (stance-level)}
For topic $t$ and condition $r$:
\[
\mathrm{AgreeRatio}(t,r)=\frac{\#\text{agree}}{\#\text{agree}+\#\text{disagree}}
\]
Agreement means the model label matches the gold stance for that row (e.g., gold=\emph{against}, model=\texttt{Disagree}).
\paragraph{LLaMA adjustment.} When \texttt{Neutral}/\texttt{Neither}/\texttt{Partial} occurs:

\[
\mathrm{AgreeRatio}^{\text{\scriptsize LLAMA}}(t,r)=
\frac{\#\text{agree}}{\#\text{agree}+\#\text{disagree}+\#\text{neutral}}
\]

where \texttt{Partially Agree} counts as \texttt{agree}; \texttt{Neither/Neutral} counts as \texttt{neutral}.

\subsection{Embedding similarity of justifications}
To compare the \emph{reasons} (beyond labels), we embed \texttt{LLM\_reason} with multilingual \textbf{LaBSE}~\parencite{feng2020labse} (768-D) and compute cosine similarity on matched rows between:
\begin{enumerate}
  \item Role-based vs.\ Assistant,
  \item Native-language vs.\ Assistant,
  \item Role-based vs.\ Native-language.
\end{enumerate}
Per topic/comparison we report mean, standard deviation, and $n$.

\section{Analysis Plan (per model)}
We run the three pairwise comparisons above, and additionally (i) summarize JSON error/refusal rates by condition, and (ii) examine topic sensitivity (which themes show the largest language-vs-role gaps). All figures/tables are generated from logged artifacts for full reproducibility.
